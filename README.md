# 🎸 JamBook

> **The Vibe is Here ✨** — A multilingual lyrics + chords app built for live jam sessions.

JamBook is a free, ad-free, single-page web app for finding song lyrics, transliterating them into Roman script (Tanglish / Hinglish / etc.), and organising them into session folders you can share with your jam group.

Live demo: **https://sudharsan040.github.io/JamBook/**

---

## ✨ Features

### 🔍 Search & Lyrics
- **Song search** powered by the iTunes catalogue (works in India — millions of songs)
- **Lyrics fetching** races multiple free sources in parallel:
  - [tamil2lyrics.com](https://www.tamil2lyrics.com) — human-curated Tanglish for Tamil songs
  - [lrclib.net](https://lrclib.net) — strong Indian + global coverage
  - [lyrics.ovh](https://lyrics.ovh)
  - some-random-api.com
  - ChartLyrics
- **First source to return real lyrics wins** — average load time under 1 second
- **Per-song result caching** in localStorage — instant reload, no extra API calls

### 🔤 Smart Transliteration (Tamil → Tanglish)
- **Custom Tamil-aware mapper** with sandhi rules, geminate handling, slang post-processing
- **Google Translate** romanization layer for context-aware output ("✨ Smart")
- **Loanword dictionary** — 200+ English-in-Tamil words rendered correctly (`cycle`, `motor`, `bike`, `pant`, `jeans`, `mobile`, etc.) instead of phonetic mush
- **Toggle** between AI/Google output and rule-based phonetic output per-song

### 📁 Session Folders
- **Create folders** for each jam session ("Friday Jam", "Wedding Set", "Vibe List")
- **Add songs from search**, or **paste your own lyrics**
- **Session queue** sidebar / drawer when a song is open — tap to skip to the next song
- **Default "Vibe List" folder** auto-created on signup

### ✏️ Add & Edit Your Own Lyrics
- **+ Add Lyrics** from the home page or any folder
- **Edit any song** — both native script AND Tanglish, independently
- **Auto-fill Tanglish** from native via the built-in transliterator (one-click starting point)
- **Vocal markers** — type or insert `[Verse]`, `[Chorus]`, `[Male]`, `[Female]`, `[Duet]`, `[Bridge]` to get coloured tags
- **Chord lines** — type chords alone on a line (`C  G  Am  F`) to render as chord rows above the lyrics

### 🎸 Chords on Demand
- **One smart "Chords" button** races Ultimate Guitar / Torrins / Genius in parallel via a CORS proxy
- Highlighted with a link when a chord sheet exists; blurred when nothing's found
- Result cached per song

### 🎵 Performance Helpers
- **Auto-scroll** with Slow / Medium / Fast speeds — sub-pixel accumulator for buttery slow scrolling
- **Romanized ↔ Native** toggle for Indic scripts
- **Big readable lyric text** (1.25rem default, easy on the eyes mid-jam)

### 🔗 Folder Sharing
- **One-click share URL** that encodes the entire folder (name + all songs + custom lyrics)
- Recipient pastes the link → app auto-prompts to import → folder lands in their account
- Works **across devices** (no localStorage handoff required)
- Native OS share sheet support on mobile

### 👥 Multi-user Cross-device Sync
- **Supabase Auth** with username + password (synthetic emails, no verification needed)
- **Cloud-synced folders** via Postgres + Row Level Security
- **Falls back to localStorage** if Supabase isn't configured (single-device mode still works)

### 📱 Mobile-first UI
- Search bar fixed to bottom for thumb reach
- Compact song view (single-line title, action icons)
- Session queue → slide-in drawer on mobile
- All hover-only actions become tap-accessible on touch

### 🔐 Per-User Privacy
- Each account's folders + custom songs are scoped via Supabase Row Level Security
- Edits to a song's lyrics are stored on **your** copy of the folder — they don't leak to other users
- Shared folders explicitly opt-in via share token

## 🚀 Deployment (GitHub Pages + Actions)

This repo is set up to deploy itself automatically.

### One-time setup

1. **Fork / clone this repo** to your own GitHub account
2. **Create a Supabase project** at [supabase.com](https://supabase.com) (free, no credit card)
   - In SQL Editor, run:
     ```sql
     create table public.folders (
       id uuid primary key default gen_random_uuid(),
       user_id uuid references auth.users not null,
       name text not null,
       songs jsonb not null default '[]'::jsonb,
       share_token text unique,
       created_at timestamptz default now()
     );
     create index folders_user_idx  on public.folders(user_id);
     create index folders_share_idx on public.folders(share_token);
     alter table public.folders enable row level security;
     create policy "owners_all"  on public.folders for all
       using (auth.uid() = user_id) with check (auth.uid() = user_id);
     create policy "share_read"  on public.folders for select
       using (share_token is not null);
     ```
   - **Authentication → Providers → Email**: turn OFF "Confirm email"
3. **Add GitHub Secrets** (Settings → Secrets and variables → Actions → New repository secret):
   - `SUPABASE_URL` — your project URL (e.g. `https://abc.supabase.co`)
   - `SUPABASE_KEY` — your `anon` public key
4. **Enable GitHub Pages** (Settings → Pages → Source: **GitHub Actions**)
5. Push any change to `main` → the workflow builds and deploys → site is live in ~45 seconds.

### Optional: Audience Song Requests

Lets anyone with a link search for a song and add it straight into a folder's
live queue — no JamBook account needed. The link is per-folder and stable
(generated once, reused forever). Requires the `folders` table above plus:

```sql
alter table public.folders add column if not exists request_token text unique;
create index if not exists folders_request_idx on public.folders(request_token);
create policy "request_read" on public.folders for select
  using (request_token is not null);
create policy "request_update" on public.folders for update
  using (request_token is not null) with check (request_token is not null);
```

In the app: open a folder → **🎤 Request Songs** → copy the link and share it
with your audience. They land on a bare search-and-add page at
`?request=<token>`, never seeing the rest of the app.

**Trade-offs worth knowing:** like the existing folder-share feature, anyone
who has the link can act on it — there's no separate password, the link itself
is the credential (a long random token, not guessable). Adding a song is a
read-then-write on the folder's song list client-side, so two people
submitting in the exact same instant could rarely clobber each other's
addition — fine for a casual jam session, not built for high-concurrency use.

### Making changes
Edit `src/app.jsx` and commit. The GitHub Action automatically:
1. Installs esbuild + react + react-dom
2. Bundles `src/app.jsx` into `dist/app.js` with secrets injected at build time
3. Uploads everything as a Pages artifact
4. Deploys to GitHub Pages

You never run anything locally.

## 🎯 How Lyrics Work (mental model)

```
User opens a song
    │
    ├─ Has custom lyrics from user?         → render those, skip API
    ├─ Cached from a previous load?         → render cached, skip API
    └─ New song:
       Race 5 free lyric sources in parallel
       │
       └─ First with valid lyrics wins → display + cache → background-romanize via Google
```

For romanization:
```
User's custom Tanglish (if saved)
    │ fall through
Google Translate transliteration (cached per song)
    │ fall through
Built-in rule-based Tamil mapper + loanword dictionary
```
